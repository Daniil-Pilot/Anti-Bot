# Cookie Bot Detection (Avito Anti-Bot)

## Задача

**Бизнес-контекст.** Объявления и контакты продавцов Avito выгружают внешние сервисы-парсеры:
автоматизированные куки массово просматривают объявления, листают выдачу и снимают контакты.
Это нагружает инфраструктуру, портит продуктовые метрики и вредит продавцам. Anti-bot команда
выявляет такие куки по журналy поведения, не трогая легитимных пользователей.

**Формулировка.** Для каждой куки задано суточное окно наблюдения
[window_start_ts, window_end_ts) и лента событий внутри него: просмотры объявлений и выдачи,
свайпы фото, избранное, страницы продавцов, контакты (телефон/чат/сообщение), login, captcha;
метаданные событий — platform, user_agent, координаты курсора, поисковый запрос и страница,
атрибуты объявления. Требуется по событиям окна присвоить cookie_id оценку ∈ [0,1] —
уверенность, что кука является бот-парсером (в train дана разметка target 0/1).

**Данные.** train.csv — 11 091 кука (8.1% ботов), окна 2026-04-06…2026-04-19;
test.csv — 4 909 кук, окна 2026-04-20…2026-04-26 (строго в будущем относительно train);
events.csv.gz — 328 905 событий, 14 колонок; sample_submission.csv — формат ответа
(cookie_id, score).

**Метрика.** Precision @ Recall ≥ 0.70: куки сортируются по score по убыванию, перебираются
пороги; ответ — максимум precision среди порогов с recall ≥ 0.70; одинаковые score учитываются
одной группой. Порог выбирает проверяющая система, поэтому решение — ранжирование,
а не калиброванные вероятности.


**Почему это сложно.** Сильный дисбаланс классов (8% ботов); боты имитируют человека
(просмотры, избранное, контакты — парсеры выгружают их целенаправленно); разнородные
платформы и user-agent; структурные пропуски (на мобильных нет курсора, у несвязанных
с поиском событий нет запроса); test лежит в будущем относительно train — значит,
валидация обязана быть временной, а не случайной.

## Подход
- Признаки считаются только по событиям окна [window_start_ts, window_end_ts)
  и причинному прошлому (строго раньше window_end_ts). События после окна (12.4% лога)
  не используются (недоступны в момент решения).
- Блоки (76 признаков): объём и микс 10 типов событий; ритм и всплески (gap-статистики,
  zero_gap_share, events_per_burst, burst_interval_cv); последовательности и переходы;
  разнообразие интересов; геометрия курсора (ptr_missing_share_web, траектория);
  согласованность platform/UA; возраст куки; причинные ко-визиты (число различных кук,
  разделивших item/UA, при первом появлении строго раньше конца окна субъекта;
  столкновения событий секунда-в-секунду).
- Обработка: drop_duplicates событий; нормализация platform (lower, iphone→ios);
  без импутации — NaN осмысленны и нативны для CatBoost/LightGBM.
- Валидация: rolling-origin, три 2-дневных «будущих» среза (04-14, 04-16, 04-18);
  метрика — из metric.py.
- Модель: Optuna-TPE (40 trial'ов, seed 42, MedianPruner) подбирает гиперпараметры
  CatBoost и LightGBM и вес их ранг-бленда; вес оценивается внутри CV.
  Финал — ранг-ансамбль top-5 trial'ов.

## Baseline и сравнение (P@R ≥ 0.7)
| Решение | Признаков | Local CV | Platform |
|---|---|---|---|
| Константа (sample_submission) | 0 | 0.081 | 0.0939 |
| 6 сырых сигналов EDA, 9 семейств моделей | 6 | 0.12–0.20 | — |
| HGB×2 + LR (поведенческие блоки) | 72 | 0.7238 | 0.6946 |
| CatBoost + LightGBM + причинные ко-визиты | 76 | 0.8197 | 0.8303 |
| + Optuna-TPE, ансамбль top-5 trial'ов | 76 | 0.8224 | 0.8240 |

Бенчмарк семейств на 72 признаках (среднее по фолдам): catboost 0.79, lightgbm 0.79,
hgb 0.78, et 0.73, lr 0.71, lda 0.48, knn 0.40, nb 0.09, константа 0.08.
Вывод: вклад обработки признаков (+0.50) больше вклада выбора семейства модели.

Отклонённые эксперименты: ко-визиты без причинного среза (темпоральная утечка,
local 0.861); self-training (−0.024); SVD/KMeans/IsoForest-блоки (абляция: нестабильность);
LightGBM до ко-визит (Δ=0.0008 < порога 0.01); пост-подбор весов на pooled
(попытка 3: local 0.853 → platform 0.816) — после этого вес оптимизируется только внутри CV.


## Результаты и ограничения
- Топ-признаки (permutation importance под метрику): ptr_move_mean, item_pop_max,
  item_pop_mean, nuniq_item_location, gap_min.
- Ограничения: срез 04-16…17 слабее (0.70–0.75 против 0.88–0.91); шум валидации
  ±0.02–0.03 (улучшения < 0.02 не принимались); ко-визиты требуют поток событий
  соседних кук на момент решения; калибровка не выполняется (метрика ранговая);
  нет IP/geo/фингерпринтов — часть ботов поведенчески неотличима от людей
  (зона перекрытия OOF-скоров 0.8–0.95).
